# 要件定義書

> 最終更新: 2026-10-09

## 1. プロジェクト概要

- **背景**: 離乳食のアレルギーチェックの手間を減らしたい。アレルギーチェックする食材の順番が分かりやすく、チェック漏れがなく、アプリ一つで完結できるようにしたい。
- **目的**: 赤ちゃんのいるママ・パパが、離乳食の導入をスムーズに進められるようにする。
- **想定ユーザー**: 生後5〜18ヶ月頃の赤ちゃんを育てている保護者（個人利用）

### スコープ

#### 含むもの
- 離乳食の時期区分（初期／中期／後期／完了期）ごとに食べられる食材の表示
- 食材ごとのアレルギーチェック記録（未チェック／食べた・問題なし／アレルギー症状あり）
- 赤ちゃんの月齢に応じた「次に試すとよい食材」の提示（チェック漏れ防止）
- 食材の一覧・カテゴリ別・時期別の表示と検索
- 特定原材料（えび・かに・くるみ・小麦・そば・卵・乳・落花生）を中心としたアレルギー注意食材の明示
- 赤ちゃんのプロフィール（名前・生年月日 → 月齢の自動計算）の登録・編集
- アレルギー症状が出たときの対応マニュアル（受診の目安・相談窓口の案内）
- スマートフォンでの利用を主とした Web アプリ（ブラウザで動作）

#### 含まないもの
- 医師による診断・医療アドバイスの提供（あくまで記録・目安の提示に留める）
- レシピ・献立の自動作成（Phase 2 で検討）
- 家族間でのデータ共有・複数端末同期（Phase 2 で検討）
- 複数の子どもの管理（Phase 2 で検討）
- ネイティブアプリ（App Store / Google Play）での配信
- 課金機能・広告
- SNS 連携・ユーザー同士の交流機能

## 2. ユーザーストーリー

**US-1**
As a 個人利用ユーザー,
I want アレルギーチェックの記録、時期別の食材表示,
So that その日の離乳食に何をあげたら良いかが一目でわかる.

**US-2**
As a 個人利用ユーザー,
I want 赤ちゃんの月齢に合わせて、まだ試していない食材を順番に提示してほしい,
So that チェック漏れなく、迷わずに新しい食材を試せる.

**US-3**
As a 個人利用ユーザー,
I want 食材を名前で検索して、食べられる時期とチェック状況をすぐ確認したい,
So that 買い物中や調理中でもすぐに判断できる.

**US-4**
As a 個人利用ユーザー,
I want アレルギー症状が出たときの対応方法をすぐに見られるようにしたい,
So that いざという時に慌てずに行動できる.

### 3.1 「次に試す食材」の提示ルール

1. 赤ちゃんの月齢で食べられる時期の食材のみを対象にする
2. 新しい食材は **1日1種類** とし、候補を2つ出してユーザーが選ぶ
3. 候補はアレルギーの心配が少ない食材から順に出す
4. 卵・乳製品・小麦など **段階的に量を増やす食材** は、他の食材と並行して進める。食べられる時期になったら早めに着手し、新しい食材の候補とは別枠（F-01b）で表示する
5. それ以外の特定原材料（えび・かに・そばなど）は、その時期の食材の中で最後のほうに少量から試す
6. 新しい食材は、すぐ受診できる平日の午前中に試すよう画面で案内する

※ 時期や量の目安は厚生労働省「授乳・離乳の支援ガイド」に準拠し、アプリ内で「かかりつけ医の指示を優先してください」と表示する。

## 4. 非機能要件

- **パフォーマンス**: スマートフォン（4G 回線）で初回表示 3 秒以内、画面遷移・検索結果の表示は 1 秒以内を目安とする。食材マスタは静的データとして配信し、サーバー通信を最小限にする。
- **セキュリティ**:
  - 通信はすべて HTTPS とする。
  - Phase 1 では記録データを端末内（ブラウザのローカルストレージ）にのみ保存し、外部サーバーへ送信しない。
  - Phase 2 でクラウド保存する場合は、認証必須とし、本人（および共有を許可した家族）以外がデータを参照できないようにする。
  - 赤ちゃんの名前は本名でなくニックネームでも登録可能とする。
- **可用性**: 無料ホスティング（Vercel 等）の稼働率に準ずる。Phase 1 は端末内保存のため、サーバー障害時でも閲覧・記録が継続できることを目指す。
- **スケーラビリティ**: 個人利用を想定し、大量同時アクセスは想定しない。食材マスタはデータファイルで管理し、コード変更なしで食材の追加・修正ができる構成とする。
- **ユーザビリティ**: スマートフォン縦画面・片手操作を前提としたモバイルファースト設計。主要操作（食材を探す→記録する）は 3 タップ以内で完了できること。
- **保守性**: TypeScript による型定義を行い、食材データ・記録データの構造を明確にする。
- **免責表示**: 本アプリは医療行為の代替ではない旨をマニュアル画面および初回起動時に表示する。

## 5. 制約条件

- **予算**: 無料枠で完結（ホスティング・データベースとも無料プランの範囲内）
- **期間**: 期限は設けない。Phase 1（MVP）は 1〜2 週間程度での完成を目安とし、使いながら Phase 2 を検討する
- **技術**:
  - フレームワーク: Next.js（App Router）+ TypeScript
  - スタイリング: Tailwind CSS
  - ホスティング: Vercel（Hobby プラン・無料）
  - データ保存: Phase 1 はブラウザのローカルストレージ（サーバー・DB 不要で無料、個人情報が外部に出ない）
  - Phase 2 でログイン・同期を行う場合は、無料枠のある DB／認証サービス（Supabase、Neon など）を検討
- **コンテンツ**: 食材の時期区分は厚生労働省「授乳・離乳の支援ガイド」の目安に準拠する。
